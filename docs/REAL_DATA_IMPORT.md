# Braun Smart Portal 真实 Excel 导入规则

本规则基于 2026-08-03 上传并核对的真实文件：

- `批发销售.20260803152156496.xlsx`
- `jin汇总1.xlsx`

## 1. 批发销售工作簿

### 汇总

此表不是标准数据库表。每行可能同时包含：客户、Excel 日期序号、订单号、应收金额、多项分散支出、安装状态、备注。

导入原则：

- 客户名称按原文保留。
- 订单号可以是数字或文字组合，例如 `823Lauren`、`Matt824`。
- 日期值如 `46225`、`46230` 按 Excel 序号转换，不当作订单号或金额。
- 应收和每项支出分开保存，不合并为单一金额。
- 未明确币种的汇总支出进入人工审核队列。
- 安装状态和备注原文保留。

### Paul

Paul 表同时包含：转账汇总、两组订单明细、订单结算差额和解释说明。

- 订单金额与差额分别保存。
- `已结清`、`不清楚` 等状态原文保留并映射到标准状态。
- 负差额不能改成正数。
- 不将组小计重复计入订单金额。

### 林

林表是往来结算表，包含项目应收、收款冲抵、结余和新单据。

- 项目应收和收款必须分别记录。
- 负数代表冲抵/付款，不应被改为支出或收入正数。
- `单号 822`、`单号 823`、`MATT` 是新增单据，不和结算汇总重复入账。

### 彭

彭表是 KT 支出明细。

- USD 列只保存美元。
- RMB/CNY 列只保存人民币。
- 禁止自动将人民币显示为美元。
- 两种币种分别汇总，不自动换算。
- 美国转账和人民币转账分别作为资金流水保存。

## 2. Jin Commerce 订单汇总

字段映射：

- PO号 → 标准化 PO，例如 `CWF67635` → `CWF 67635`
- 客户名字 → Dealer
- 项目代号 → Sidemark
- 产品类型 → Order Item Product Type
- 数量 → Qty
- 以前发邮件 → Previous Emailed Amount
- 结算金额 → Settlement Amount USD
- 已到账金额 → Remittance Amount USD
- 差额 → Difference USD
- 汇款 → Remittance Status

特殊规则：

- 同一 PO 可以包含多行 Roman/Drapery，不能因 PO 相同而删除重复行。
- 已到账金额可能覆盖多个 PO。保存原始合并汇款说明，并进入汇款分配界面人工拆分。
- 空金额保持为空，标记待核对，不自动填 0。
- 异常长数字通常是多张 PO 拼接，标记人工审核，绝不作为金额。
- 金额保留原始值及标准两位小数值，方便追溯。

## 3. 数据安全

- 导入前生成批次编号和文件哈希。
- 同一文件重复上传时先比较哈希，避免重复导入。
- 导入先预览，不直接写正式订单。
- 人工确认后才提交。
- 每条记录保存来源：文件名、工作表、原始行号。
- 可按导入批次回滚。
