# V5.1 只读关联预览验收记录

实现入口 `/v5/order-preview`；只读 API `GET /api/v5/order-preview`。仅在隔离开发环境实现，未部署生产、未执行迁移。没有确认写入接口，Owner 也不能在本阶段保存关联。

| 要求 | 本轮实现与验证 |
|---|---|
| 读取旧单、V4、报价、发票、窗口和生产 | 读取旧 quotes/customer_orders、orders、正式报价/签名、两类发票、项目/窗口/测量、加工图/工厂分配/生产单；列清单明确排除凭据 |
| 分类 | 明确引用、待审核、冲突、孤立/缺失引用；明确引用不代表已统一订单 |
| 保留原值 | 展示原字段及客户资料；候选比较保留两边原单号、原始金额和币种，未修改或合并 |
| Owner 限制 | 服务端只允许有效 Owner 会话读取审核资料；其他四种角色 403；未登录/撤销会话 401。确认功能尚未开放，并非已实现确认工作流 |
| 严格只读 | 仅 SELECT；独立只读会话查询不调用带账号恢复写入的通用鉴权。存在恢复配置时拒绝读取；无审计写入或 session 刷新 |
| 冲突 | 跨客户、重复候选来源、金额/币种不一致、缺失引用、签名哈希冲突、生产冻结版本冲突均有稳定代码与中文说明 |
| 隔离验证 | 空内存 SQLite 重放现有迁移；虚构数据；query_only=ON 请求成功；全部表前后快照一致；10 项自动测试通过，TypeScript 检查和本地 Vite 构建通过 |

候选关联只比较用户明确输入的旧 customer_orders.id 与 orders.id，不依据姓名/地址/邮箱自动推荐或保存。同邮箱仅是人工审核证据，不是已确认身份。当前没有读取或写入尚未启用的 v5_order_sources 草案表；重复来源检测范围为本次最多 100 个候选。页面提供单对比较，API 支持多个候选。历史确认、持久化映射及完整多来源批量审核属于下一阶段。

金额差异为需复核提示，不自动判定哪边正确；正式报价选配差额可能导致账单与基础 total 不同。旧发票金额保留于 snapshot_json，当前不自动解析所有历史快照格式来认定金额一致。跨表读取不保证同一时间点快照，不可作为直接写入的依据。

每表最多 5000 条，超限返回 413，不返回截断分类；读取失败返回 503，不伪装为零记录。返回 private/no-store。页面采用可换行卡片与原字段折叠，避免宽表阻挡手机操作；尚未完成真机/浏览器视觉验收，不能声称移动端验收全部通过。

运行：`node --test tests/v5-order-preview.test.mjs`。正式迁移讨论仍以前述完整备份、历史副本对账、原子确认服务及业务验收为前提。
