# Braun Smart Portal V5.0：订单只录入一次

确认日期：2026-10-11。最高实施优先级；本文是需求与验收约定，不代表功能已经实现。

## 统一业务主线

1. 使用同一个不可变订单 ID 串联客户、项目、窗口、报价、发票、采购、物流、安装及财务。各模块保留自己的记录 ID，通过订单 ID 关联；客户可以拥有多个订单，不能把客户 ID 当订单 ID。
2. 客户名称、地址、电话、产品、尺寸、数量从统一记录带入。Braun、Jin、Z 系列及人工录入共用订单入口；来源映射持久化，重复提交与重试不产生重复订单。
3. 报价确认、定金收齐、工厂下单、发货、安装完成通过明确状态规则联动。保留部分采购、部分发货、部分安装的明细状态，不能把部分完成误标为整单完成。
4. 一个订单支持多个供应商、多笔材料费、加工费、运费及供应商付款，并能追溯原始单据。
5. 应收、已收、未收、应付、已付、未付与利润关联订单。人民币与美元分别汇总；仅在记录明确汇率、日期和来源后换算，不能直接相加。区分预计利润和实际利润，避免发票与收款、费用与付款重复计入。
6. 修改尺寸、价格或状态时保存操作者、时间、原因、前后值及版本。未签发草稿同步更新；已签发报价、发票、加工单保留不可变快照，修改必须生成可追溯新版本，不得覆盖原件。

## 正式生产下单的强制条件

用户已确认：默认门槛采用 **客户已确认报价中的应收定金**，保留按订单明确设置金额的能力。

- 必须存在有效的客户确认报价，且与当前拟生产的内容和版本一致。
- 已到账、已入账且关联该订单的有效收款达到应收定金；待处理、失败、撤销及未到账款项不算到账。退款应扣除，非现金贷项不能冒充收到款项。
- 金额和币种必须可核对；未指定金额或币种不能按零自动放行。零定金必须是明确确认的业务设置并留下记录。
- 创建正式供应商生产单、草稿转正式以及直接修改订单到生产状态都必须在服务端校验，不能只禁用界面按钮。
- 并发提交、重复请求及校验后数据变化不能绕过门槛；使用事务或等价原子约束，并保证幂等。
- 已确认报价发生需要重新确认的修改时，未正式下单部分必须重新满足确认和收款条件。已发出的生产文件保留原版本，通过变更单通知后续业务；退款或撤回确认产生可追溯异常，不悄悄删除历史生产记录。

## 验收场景

- 从任一报价系统录入一次含多个窗口的订单，报价、发票、供应商单、物流、安装及财务显示同一订单 ID，客户资料不需再录。
- 一个订单分给两家工厂，分别添加材料、加工、运费和付款；每笔费用可回到订单和供应商，汇总无重复。
- 未确认报价、有确认但未付款、定金不足、失败付款、仅有贷项均不能正式下单；有效到账恰好达到定金可下单。
- 在收款变化、报价更新和同时下单情况下验证服务端门槛；重复请求只生成一份对应生产单。
- 修改窗口尺寸或报价价格后，草稿同步；旧签发文件及其哈希不变，重新签发保留版本链。
- CNY/USD 分币种准确对账；缺汇率时不显示误导性的合并利润。
- 手机和平板可完整打开录入表单、滚动、保存、查看各版本文件及填写取货时间。
