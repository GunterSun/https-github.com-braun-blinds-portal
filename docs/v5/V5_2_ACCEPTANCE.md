# V5.2 历史订单审核工作台（只读）

本轮继续使用 `/v5/order-preview` 和 Owner 专用 `GET /api/v5/order-preview`，替换 V5.1 的全表批量读取。无迁移、无确认写入、无生产部署。V5.1 文档保留为历史记录；当前行为以本文为准。

## 已实现

- 主记录采用 ID 游标分页，默认 25 条，最多 50 条；支持上一页/下一页。筛选变化重新从第一页开始。
- 旧订单、V4 订单、旧报价、正式报价、两类发票、窗口、加工图和生产单可分别检查。只补读本页明确引用的 ID，逐层查到客户/项目/测量/签名；不因未分页读取的记录而误报孤立。引用拓展过大或未完成时返回失败，不生成残缺结论。
- 订单和正式报价/账单按单号及客户资料搜索，支持创建日期区间。旧发票仅按发票号，加工图仅按 ID，生产单按工厂名/单号，界面明确说明；搜索中的 `%`、`_` 为文字，不作为通配符。
- 本页分类统计、分类筛选及原始字段/引用详情；统计不是全库统计。游标跨请求不是一致性快照，数据变化时应重新审查。
- 旧单卡片直接查找候选，不要求用户记住数据库 ID。候选依据为邮箱、项目名或展示编号相同，各自注明不足以确认身份。候选每批 20 条，可继续下一批；未命中不能推断不存在关联。
- 零售、批发、折扣百分比/金额、小计、运费、税费、安装费、定金和总额分开显示。来源没有单独字段时显示未记录，不当成零。不同币种不换算，旧批发与 V4 总额不默认为相同口径。
- 仅金额不同的账单/报价列为待审核，不直接认定数据损坏；客户/窗口不一致、签名哈希和生产冻结版本不一致仍明确提示冲突。
- 缺失文档哈希、旧发票快照缺失/不可解析提示缺少原件证据。这不等于已核验 R2/PDF 文件存在性；本轮不访问文件存储。
- 审核意见仅保存于页面内存，刷新、换页或切换候选即丢失；无保存按钮、无 localStorage、无确认接口。

## 接口边界

分页参数：source、q、from、to、after、size。候选模式：mode=candidates、legacyId、after。V5.1 的 pairs 比较模式已被候选工作台替换，不应继续使用旧调用方式。候选只是临时搜索线索；重复持久映射需在下一阶段的来源映射存储中核验，不能声称本轮已有完整持久来源去重。

所有业务 SQL 均为 SELECT，保留只读会话校验、Owner 权限、恢复配置时拒绝读取和 private/no-store。POST 始终 405，任何角色都不能确认关联。没有启用 SQL 迁移草案。

分页限制的是返回记录和引用拓展量，不代表任意规模查询都已经达到性能目标：文字包含搜索与多字段候选条件可能扫描表。真实数据量下的查询计划、时延及索引方案须在隔离副本测量；本轮没有生产索引变更或全库 COUNT 扫描。

## 下一阶段持久审核设计（未实现）

正式审核意见不能只存字符串：应保存来源类型/ID、目标 orders.id、审核者、理由、决定、时间、当时金额口径、来源版本/哈希和目标订单版本，以及幂等键。提交确认时在同一事务重新核验这些版本与客户范围，并原子保存映射和审计。预览过期或来源变化必须返回冲突，不能沿用浏览器旧结果。不同意见保留追加历史，不覆盖先前决定。

## 本轮验证

`node --test tests/v5-order-preview.test.mjs`：15 项通过，涵盖只读数据库和全表记录不变、各非 Owner 角色拒绝、撤销会话、禁用确认、候选证据、输入验证、签发版本、订单命名空间、错误处理、游标/客户/日期搜索、跨页引用补读、查询范围、金额口径及缺少原件证据。

TypeScript 检查、本地 Vite 构建通过。测试采用隔离内存 SQLite 和虚构客户，不写生产数据。iPhone/iPad/电脑实际浏览器长订单视觉验收尚未完成；响应式卡片实现不能代替真机验收。生产全量数据、R2 文件和价格业务验收仍待验证，不开放历史关联写入。
