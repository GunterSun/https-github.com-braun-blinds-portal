# BRN-009 Braun AI 助理 — 架构与安全

## 1. 架构原则

AI 不直接访问数据库表，也不允许自由生成 SQL。所有读取和写入都必须通过经过权限检查的业务工具层。

```text
用户
  ↓
统一登录与角色权限
  ↓
AI Orchestrator
  ↓
允许调用的业务工具
  ├── Order Search
  ├── Customer Search
  ├── Invoice & Payment Read
  ├── Expense & Profit Read
  ├── Logistics Read
  ├── Installation Read
  └── Draft / Confirmed Actions
  ↓
统一业务数据库
```

## 2. 工具层要求

每个 AI 工具必须定义：

- 工具名称和用途
- 允许角色
- 必填参数
- 返回字段
- 查询范围
- 最大记录数
- 是否只读
- 是否需要用户确认
- 审计日志动作名称

禁止使用一个“万能数据库查询工具”。

## 3. 权限继承

AI 必须完全继承门户现有权限：

- 当前登录用户
- 角色
- 客户归属
- 订单分配
- 工厂分配
- 安装任务分配
- 字段级隐藏规则

AI 不得因为自然语言提问而绕过任何页面或 API 权限。

## 4. 数据最小化

- 只取回答所需字段。
- 默认限制返回条数。
- 客户查询不返回内部成本。
- 工厂查询不返回客户利润。
- 安装工只得到完成任务所需信息。
- 日志、原始 Excel 数据和利润默认仅 Owner 可见。

## 5. 财务安全

- 所有金额必须同时返回 `amount` 和 `currency`。
- 禁止跨币种直接相加。
- 如需折算，必须使用明确汇率、日期和来源，并单独显示原币。
- AI 不得自行猜测付款、退款或支出分类。
- 财务写入必须经过预览、确认、幂等检查和审计。

## 6. 防止提示注入

AI 从 PDF、Excel、备注、邮件或文件中读取到的文字都视为业务数据，不视为系统指令。

必须忽略文件中诸如以下内容：

- 要求泄露其他客户信息
- 要求忽略权限
- 要求执行外部命令
- 要求发送付款或删除数据

## 7. 操作分级

### Level 0：只读

查询、汇总、解释和页面跳转。

### Level 1：生成草稿

生成 Quote、Invoice、邮件、短信、采购或物流草稿，不自动发送。

### Level 2：需确认写入

更新状态、记录付款、创建任务等。必须显示：

- 即将修改的对象
- 修改前值
- 修改后值
- 影响范围
- 操作人

用户明确确认后才执行。

### Level 3：禁止自动执行

- 删除正式订单
- 删除付款或支出
- 发起退款
- 改变银行或 Stripe 密钥
- 修改角色权限
- 批量覆盖数据库

这些操作只能进入专门管理流程。

## 8. 审计

记录：

- 用户 ID 和角色
- 提问摘要
- 调用的工具
- 访问的实体 ID
- 是否包含财务数据
- 操作预览
- 用户确认
- 执行结果
- 错误与拒绝原因

敏感提问原文可根据隐私策略脱敏保存。

## 9. 准确性与来源

回答必须区分：

- `数据库事实`
- `计算结果`
- `系统建议`
- `缺失或待核对信息`

关键结论应提供可点击来源：订单、Invoice、付款、物流或安装页面。

## 10. 可用性与故障处理

- AI 服务不可用时，门户核心订单功能仍必须正常。
- 工具调用失败时，不得用猜测填补。
- 超时后显示已完成和未完成的部分。
- 写入失败不得留下部分状态；使用事务或幂等恢复。
