# BRN-019 Release & Quality Center — 产品需求

## 1. 目标

建立统一的发布、测试、数据质量和回滚中心，明确区分代码已合并、测试环境已部署、正式环境已部署和数据库迁移已完成，避免把 GitHub 合并误认为网站已经上线。

## 2. 核心页面

- `/release-center`：版本、环境和发布状态总览。
- `/release-center/releases`：版本记录、变更、负责人和结果。
- `/release-center/tests`：自动测试与人工验收结果。
- `/release-center/data-health`：重复、缺失、异常金额和币种问题。
- `/release-center/deployments`：GitHub、构建、数据库、域名和线上验证状态。
- `/release-center/rollback`：允许的回滚方案、备份和执行记录。

## 3. 发布状态

每个版本分别记录：

1. `documented`：需求和测试文档已完成。
2. `implemented`：代码已完成。
3. `merged`：代码已合并到主分支。
4. `staging_deployed`：测试环境已部署。
5. `staging_verified`：测试环境验收通过。
6. `production_deployed`：正式环境已部署。
7. `production_verified`：真实域名和关键流程验证通过。
8. `rolled_back`：版本已回滚。

不得跳过状态或用一个状态代替另一个状态。

## 4. 必测业务流程

- 登录和五级权限。
- 五位数订单与 Invoice 编号。
- Braun/Jin 报价规则。
- 一页 Invoice PDF 不为空。
- Stripe 与手工付款幂等。
- USD 与 RMB 严格分离。
- Excel 预览、确认、去重和回滚。
- 客户、订单、工厂、物流和安装关联一致。
- 手机、平板和电脑端关键操作。

## 5. 数据健康检查

系统定期检查：

- 重复客户、订单、Invoice、付款和导入批次。
- 缺失币种、订单号、客户或来源。
- 空金额被错误写成 0。
- 付款总额与 Invoice 状态不一致。
- 已付款但余额不为 0。
- RMB 被标为 USD 或跨币种直接相加。
- 孤立的工厂、物流、安装或财务记录。
- 旧门户与统一门户之间的数据分叉。

自动检查只能生成问题和建议；批量修复必须预览并由 Owner 确认。

## 6. 发布包

每个版本必须包含：

- 版本号和发布日期。
- 对应 BRN 编号与 PR。
- 功能变更和修复。
- 数据库迁移与备份要求。
- 环境变量变化。
- 自动测试和人工验收结果。
- 已知问题。
- 回滚步骤。
- 正式环境验证证据。

## 7. 权限

- Owner：查看全部、批准生产发布和回滚。
- 开发/管理员：创建发布候选、运行测试和部署测试环境。
- Sales、Factory、Installer：参与与其业务相关的验收。
- Customer：不访问内部发布中心。

生产发布、数据库破坏性迁移和回滚必须由 Owner 明确确认。

## 8. 完成标准

- 能清楚显示同一版本在代码、测试、数据库、部署和域名上的独立状态。
- 关键业务流程有自动测试或明确人工验收记录。
- 数据健康问题可以下钻到真实记录。
- 发布失败不会被标记为成功。
- 每次生产发布都有备份、回滚和线上验证记录。
