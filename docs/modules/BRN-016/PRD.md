# BRN-016 Workflow Engine — 产品需求

## 1. 目标

在 Braun Smart Portal 中建立可审计、可暂停、可重试的业务流程引擎，把报价、订单确认、Invoice、收款、工厂生产、物流、安装、售后和经营提醒连接起来。

流程引擎用于执行明确规则，不代替人工判断，也不得绕过五级权限、金额校验或确认流程。

## 2. 核心业务流程

### 2.1 标准订单流程

`草稿报价 → 客户确认 → 正式订单 → Invoice → 定金/付款 → 工厂生产 → 发货 → 安装 → 完工 → 回访 → 财务结算`

每一步必须保存：

- 触发事件
- 当前状态
- 前置条件
- 执行动作
- 执行人或系统身份
- 时间
- 结果
- 错误和重试记录

### 2.2 付款流程

- Invoice 发出后进入待付款。
- 支持定金、部分付款和全额付款。
- Stripe webhook、Zelle、支票、现金和 ACH 都必须统一生成付款记录。
- 付款不足时不得自动标记为已付款。
- 退款、撤销和超额付款进入专门人工流程。

### 2.3 工厂流程

- 订单满足生产条件后生成工厂任务草稿。
- 多工厂订单分别跟踪材料、加工、交期、付款和发货。
- 未经授权不得自动向工厂发送包含客户利润或内部价格的资料。

### 2.4 物流流程

- 工厂或仓库标记可发货后创建物流任务。
- 每箱尺寸、重量和超长标识必须完整。
- 报价、购买运单和最终费用分开保存。
- Tracking 变化可触发客户通知草稿和内部异常提醒。

### 2.5 安装流程

- 到货或人工确认后创建安装排期草稿。
- 安装工只看到分配任务需要的信息。
- 完工需要照片、状态和可选客户签字。
- 完工后触发余额检查、回访和售后保修记录。

## 3. 触发方式

- 业务事件：Quote accepted、Invoice issued、Payment received、Factory completed、Shipment delivered、Installation completed。
- 时间事件：付款逾期、工厂超期、物流停滞、安装前提醒。
- 人工事件：Owner 或授权员工点击开始、暂停、继续或重新执行。
- AI 建议：AI 只能提出启动建议或生成草稿，不能绕过确认直接执行高风险动作。

## 4. 自动化等级

### Level 0：只提示

显示待办、异常和建议，不写入业务数据。

### Level 1：自动生成草稿

生成邮件、短信、工厂任务、物流询价或安装任务草稿，等待人工确认。

### Level 2：低风险自动执行

仅执行预先批准的内部动作，例如创建待办、更新非财务内部标记、记录 webhook 事件。

### Level 3：必须人工确认

- 发送客户或工厂消息
- 创建正式 Invoice
- 记录手工付款
- 购买运单
- 修改订单关键状态
- 创建或变更安装排期

### Level 4：禁止流程引擎自动执行

- 删除订单、付款或支出
- 发起退款
- 修改用户角色和权限
- 修改银行、Stripe 或部署密钥
- 批量覆盖数据库

## 5. 页面

- `/workflows`：流程模板与状态总览。
- `/workflows/runs`：运行历史、失败和重试。
- `/orders/[orderNumber]/workflow`：单个订单时间线。
- `/settings/workflows`：Owner 配置启停、提醒时间和审批人。

## 6. 权限

- Owner：查看全部、配置模板、暂停、重试和审批高风险动作。
- Sales：操作分配订单的销售、Quote、Invoice 草稿和客户沟通步骤。
- Factory：仅更新分配工厂任务。
- Installer：仅更新分配安装任务。
- Customer：仅查看允许公开的进度，不可操作内部流程。

## 7. 关键原则

- 同一事件重复到达只能产生一次有效结果。
- USD 与 RMB 不得跨币种自动相加。
- 任何自动状态变更都必须有可追溯来源。
- 流程失败不得阻塞门户核心订单功能。
- 代码合并、数据库迁移和线上部署状态必须分别记录。
