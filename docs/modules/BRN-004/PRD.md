# BRN-004 Quote / Invoice / Payment Center — 产品需求

## 1. 目标

建立统一的报价、Invoice 与收款中心，把 Braun/Jin 计算器、客户折扣、税、安装费、运费、付款状态和 PDF 集中到同一订单中。系统必须支持真实业务，不得生成空白文件、假付款状态或无法操作的按钮。

## 2. Quote

- 从 Braun、Jin、手工输入或 Excel 审核记录生成报价草稿。
- 支持多产品明细、数量、尺寸、款式、面料、单价和备注。
- 支持客户级默认折扣，也允许授权用户逐单调整。
- 支持税、安装费、运费、其他费用与明确的计算顺序。
- 支持客户的客户信息；对终端客户版本隐藏批发价、内部成本和利润。
- Quote 必须版本化；已发送版本不可静默覆盖。
- 客户接受 Quote 后可生成或关联唯一订单，不得重复创建订单。

## 3. Invoice

- Invoice 使用五位数编号并由服务端统一生成。
- 支持一页式和必要时多页式 PDF；文字大小、行高和分页适合打印与手机查看。
- 支持 Draft、Issued、Partially Paid、Paid、Overdue、Void、Refunded 状态。
- 支持到期日、付款条款、备注、公司信息、客户信息和工程地址。
- 已发送 Invoice 不得直接覆盖；修改金额时生成新版本、调整单或作废重开。
- PDF 生成后必须校验非空、金额一致、币种正确和文件可下载。

## 4. Payment

支持：

- Stripe 信用卡
- Zelle
- Check
- Cash
- ACH
- Wire
- 其他经 Owner 配置的方法

要求：

- 支持定金、部分付款、多笔付款、退款和超额付款。
- Stripe webhook 验签后更新付款，不能仅凭前端返回标记 Paid。
- 手工付款必须记录金额、币种、方式、日期、参考号、备注和操作人。
- 付款不得覆盖原记录；退款、撤销和冲正保存独立记录。
- Invoice 已付金额和余额由有效付款实时汇总。

## 5. 邮件与客户交付

- Quote、Invoice、付款收据和催款通知均先生成草稿或预览。
- 发送前显示收件人、主题、附件和正文。
- 发送结果、失败原因和时间写入联系记录与审计日志。
- 客户门户只能查看明确公开的 Quote、Invoice、收据和付款状态。

## 6. 页面

- `/quotes`
- `/quotes/[quoteNumber]`
- `/invoices`
- `/invoices/[invoiceNumber]`
- `/payments`
- 订单工作区内的 Quote、Invoice、Payment 标签

列表支持按客户、订单号、Invoice、状态、日期、余额和付款方式搜索。

## 7. 权限

- Owner：全部查看、配置、作废、退款审批和财务审计。
- Sales：管理分配客户/订单的 Quote 和 Invoice 草稿；付款权限由 Owner 配置。
- Factory / Installer：不可查看销售价格、付款、成本或利润。
- Customer：只查看自己的公开文件、应付金额和付款状态。

所有权限必须服务端执行。

## 8. 币种与金额原则

- 销售 Invoice 默认 USD，但必须显式保存币种。
- RMB 工厂成本不得进入客户 Invoice，也不得误标为 USD。
- 金额使用定点小数，不使用浮点数直接计算。
- 折扣、税、安装费、运费和总额的公式必须统一并可审计。
- 空金额保持空，不自动变为 0。

## 9. 完成标准

- Quote 到 Invoice 到付款的完整流程可运行。
- 支持部分付款并正确更新余额。
- Stripe 与手工付款均具备幂等和审计。
- PDF 非空、金额准确、版式可打印。
- 角色权限、客户隐藏规则、USD/RMB 规则通过测试。
- 合并代码、数据库迁移、测试环境和正式部署状态分别记录。
