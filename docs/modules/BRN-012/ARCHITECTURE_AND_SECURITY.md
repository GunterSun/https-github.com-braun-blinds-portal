# BRN-012 Knowledge Center — 架构与安全

## 1. 架构

```text
上传/连接资料
  ↓
文件安全检查与哈希去重
  ↓
原始文件存储（不可变版本）
  ↓
解析/OCR/表格提取（异步）
  ↓
内容分段与元数据
  ↓
关键词索引 + 向量索引
  ↓
权限过滤检索层
  ↓
门户搜索 / AI 助理 / AI Agent
```

## 2. 数据实体

- `knowledge_documents`：资料主记录、分类、拥有者和可见范围。
- `knowledge_versions`：版本号、文件引用、SHA-256、状态、语言和发布时间。
- `knowledge_chunks`：解析后的分页或分段内容、页码、工作表和单元格范围。
- `knowledge_tags`：产品、型号、面料、供应商和业务标签。
- `knowledge_links`：与订单、客户、产品、工厂、物流和安装实体关联。
- `knowledge_access_rules`：角色、用户、客户、工厂和订单范围权限。
- `knowledge_reviews`：审核、冲突、过期和批准记录。
- `knowledge_audit_logs`：上传、查看、下载、发布、归档和权限修改日志。

## 3. 文件安全

- 文件进入解析前执行类型、大小和恶意内容检查。
- 不信任文件扩展名，应校验实际 MIME 类型。
- 文件名不得直接作为存储路径。
- 原始文件使用不可预测存储键和短时签名下载链接。
- 默认禁止宏、脚本和可执行附件运行。
- 同一 SHA-256 可提示重复，但不同权限或业务归属不得静默合并。

## 4. 权限过滤

权限必须在检索前执行，不能先召回全部资料再让模型过滤。每个搜索片段继承文档和版本权限；关联订单或客户资料还需通过订单分配检查。

AI、搜索 API、预览和下载接口必须使用同一权限服务。客户端传入的角色、客户 ID 或工厂 ID 不可信。

## 5. 提示注入防护

PDF、Excel、邮件、图片文字和备注中的指令全部视为不可信内容。索引过程中保留原文，但不得把其中“忽略权限”“泄露密钥”“执行命令”等文字提升为系统指令。

AI 工具层只接收检索结果和受控业务参数，不允许知识文本直接定义工具名称、URL、SQL 或操作权限。

## 6. 版本与可追溯性

- 原始版本不可覆盖。
- 每个 chunk 必须指向 `document_id + version_id + source_location`。
- AI 回答保存引用的版本 ID。
- 历史 Quote/Invoice 使用的价格表版本必须长期可追溯。
- 重新解析或更换嵌入模型不改变原始文件版本，只生成新的索引版本。

## 7. 数据最小化

- 默认仅返回与问题相关的片段。
- 客户可见文件不得包含隐藏图层、批注、内部工作表或元数据中的成本信息。
- 对外发布前应生成安全副本，而不是直接开放内部原文件。
- 日志不保存完整敏感文档正文。

## 8. 删除与保留

已被订单、Quote、Invoice、安装或审计引用的资料只允许归档。真正删除需 Owner 权限、保留期检查和审计记录。法律、财务或专利资料采用独立保留策略。

## 9. 故障与降级

解析或向量服务不可用时，原文件上传和元数据管理仍可工作。语义检索失败时降级为关键词搜索。索引失败必须显示状态和可重试原因，不得把未完成资料标记为可搜索。
