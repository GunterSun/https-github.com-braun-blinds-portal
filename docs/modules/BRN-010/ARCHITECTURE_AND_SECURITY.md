# BRN-010 Braun AI Agent — 架构与安全

## 1. 架构

```text
Scheduler / User Request
        ↓
Agent Orchestrator
        ↓
Policy Engine（角色、订单分配、字段权限、操作级别）
        ↓
Approved Business Tools
        ↓
Unified Portal Database / Approved External APIs
```

Agent 不直接访问数据库，不生成自由 SQL，不直接调用浏览器自动化或外部平台。所有能力必须通过白名单工具实现。

## 2. Agent 注册表

每个 Agent 必须定义：

- `agent_id` 和版本
- 目标与允许场景
- 允许角色
- 允许工具
- 最大记录数和超时
- 是否允许计划运行
- 操作级别上限
- 是否需要人工确认
- 通知渠道
- 数据保留周期

## 3. 权限与隔离

- 当前登录用户发起的 Agent 继承该用户全部权限限制。
- 计划任务以创建者身份和授权范围运行，不得使用无限制系统身份。
- Customer 只能访问自己的订单和客户可见文件。
- Factory 不能读取内部利润、其他工厂任务或完整客户财务。
- Installer 只能读取分配给自己的安装任务所需数据。
- Owner 才能启用财务、批量任务和项目经理 Agent。

## 4. 人工确认

Level 2 操作采用两阶段流程：

1. `propose`：生成不可执行的操作预览和一次性确认令牌。
2. `confirm`：重新校验权限、数据版本、金额、对象和令牌后执行。

令牌必须绑定用户、Agent、动作、目标对象、参数摘要和到期时间。数据变化后原令牌失效。

## 5. 禁止操作

Agent 不得自动：

- 删除订单、Invoice、付款、支出或客户。
- 发起退款或转账。
- 修改角色、密码、Session、API 密钥或支付配置。
- 批量导入未经审核的 Excel 数据。
- 在未确认的情况下发送邮件、短信或客户通知。
- 声称代码合并等于线上部署。

## 6. 外部内容与提示注入

邮件、PDF、Excel、备注、网页和客户文字全部视为不可信数据。内容中要求忽略权限、调用工具、泄露数据或修改系统的指令必须被忽略。

## 7. 审计与可恢复性

每次运行记录：

- Agent、版本、触发方式和创建者
- 权限范围和输入摘要
- 工具调用、对象 ID 和结果
- 草稿、建议和警告
- 人工确认人、时间和确认令牌
- 写入前后值
- 错误、重试和最终状态

写入工具必须支持幂等键和事务。部分失败时不得留下错误的业务状态。

## 8. 成本与限流

- 每个 Agent 设置每日调用上限、最大运行时间和最大记录数。
- 大批量任务拆分为可恢复批次。
- Owner 可查看模型调用量和估算成本。
- 超出限制时暂停并提示，不得静默继续。

## 9. 故障降级

AI 或模型服务不可用时：

- 订单、Invoice、付款、物流和安装页面继续正常工作。
- 已排队的写入不得自动重试到重复执行。
- 系统显示清楚的失败原因和可重试选项。
