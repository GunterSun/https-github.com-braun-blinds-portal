# BRN-006 Logistics / Shipping Center — 产品需求

## 1. 目标

在统一门户中集中管理 UPS、FedEx、USPS、Shippo 及后续承运商的询价、比价、购买运单、标签、Tracking、异常和最终运费。所有物流记录必须关联真实订单，并支持多箱、超长件和历史相似运输推荐。

## 2. 核心功能

- 从订单、客户和仓库读取发件人与收件地址。
- 支持一个订单多个 Shipment、一个 Shipment 多个 Package。
- 每箱记录长、宽、高、重量、单位、包装类型和超长标识。
- 同时保存报价、预计到达、服务等级和附加费。
- 购买运单前展示完整预览，并由授权用户确认。
- 保存承运商、服务、Tracking、标签、购买金额和币种。
- Tracking 状态统一为 label_created、in_transit、out_for_delivery、delivered、exception、returned、unknown。
- 保存最终账单金额，与报价差异分开显示。
- 支持取消标签、退款状态、重新购买和补发，但必须保留历史。
- 支持客户通知草稿和内部异常提醒。

## 3. 超长件规则

窗帘杆、轨道和长箱必须记录最长边、周长、计费重量及承运商限制。系统不得仅根据历史经验宣称可寄，必须标明报价来源、时间和限制。USPS 或其他承运商不可用时显示原因，不生成虚假价格。

## 4. 历史成本分析

系统按尺寸、重量、区域、承运商和服务匹配相似历史运输，显示：

- 报价与最终费用
- 到货时长
- 破损、延误和退件情况
- 是否有超长附加费

推荐结果必须标记为“历史参考”，不是实时保证。

## 5. 页面

- `/logistics`：待发货、运输中、异常、已送达。
- `/logistics/quotes`：多承运商报价比较。
- `/logistics/shipments/[id]`：箱规、标签、Tracking、费用和事件。
- `/orders/[orderNumber]/shipping`：订单物流时间线。
- `/logistics/history`：历史运输成本分析。

## 6. 权限

- Owner：全部查看、购买、取消、调整和导出。
- Sales：管理分配订单的询价、通知和查看 Tracking；购买权限可配置。
- Factory：仅更新分配工厂的包装和发货资料。
- Installer：只查看与安装任务相关的到货状态。
- Customer：只查看允许公开的 Tracking 和预计到货，不查看内部成本。

## 7. 关键原则

- 地址修改后不得改变已购买运单的地址快照。
- USD 与 RMB 严格分开；物流购买通常为 USD，但不得默认改写来源币种。
- 重复点击或重复 webhook 不得创建第二张有效标签。
- 购买、取消、退款和人工改价必须审计。
- 外部接口失败时状态显示 failed 或 unknown，不得假装成功。
- 合并代码不等于外部门户已部署。
